# EPS 이력 복구와 20D 시간순 검증 — 2026-11-01

결론: EPS 수집·재표준화 결함 수정 및 실제 DB 355건 복구를 완료했다. 동일 시간순 주 평가에서 V9 평균 오차는 소폭 감소했으나 신뢰구간이 0을 포함한다. 전체 OOF 수익률 오차는 오히려 소폭 증가했고, 사전 고정한 후보 선택 절차도 복구 후 V9보다 나빴다. 안정적인 예측 개선은 입증되지 않았으므로 운영 가중치·후처리를 변경하지 않는다.

## 1. 원본에서 표준화까지 확인한 손실 경로

SEC companyfacts의 각 concept 배열에서 마지막 80개 관측치만 보존했다. 비교 공시가 반복되는 EPS 배열에서는 오래된 실제 EPS가 잘리지만, 관측 수가 적은 다른 회계 항목은 남았다. 따라서 표준화 행에 매출·현금흐름은 있고 EPS만 없는 현상이 생겼다. 원본 배열은 단순한 연도별 고유 값 목록이 아니다.

| 종목 / 회계기간 | 실제 원본 EPS (USD/shares) | 원본 accession / filed |
|---|---:|---|
| AAPL FY2016 | 8.31 | 0001628280-16-020309 / 2016-10-26 |
| MSFT FY2017 | 2.71 | 0001564590-17-014900 / 2017-08-02 |
| JNJ 2019Q1 | 1.39 | 0000200406-19-000033 / 2019-05-01 |

세 관측 모두 같은 accession의 다른 재무 항목은 DB에 있으나 해당 EPS 원본은 없었다. 추가로 일반 refresh가 이번에 들어온 제한된 입력만으로 기존 표준 이력을 삭제·재생성하여, 이미 보존한 과거 원본이 있어도 표준 이력이 축소될 수 있었다.

수정 사항:

- 기본 concept 제한을 80에서 0(전체 이력)으로 변경했다. 명시적인 양수 제한은 기존의 제한 동작을 유지한다.
- 일반 refresh는 원본 저장 후 DB의 전체 원본 합집합에서 표준화를 재구성한다.
- 두 공개 rebuild 진입점 모두 삭제와 삽입을 하나의 트랜잭션으로 묶었다.
- 기간별 행은 실제 해당 키의 CIK를 보존한다.
- 기간 길이·발행사·통화·주당 단위·당시 공시 여부를 완화하지 않았다. 연간 EPS 자리에 4분기 단독 EPS를 넣지 않는다.

SEC API의 배열·단위·공시 구조는 [SEC 공식 API 문서](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)를 참고한다. 이번 원본은 현재 다운로드한 companyfacts이며, 과거 당시 저장된 API 응답이라고 주장하지 않는다. 역사적 사용 가능성은 원본 accession·공시일·기간 근거로 제한했다.

## 2. 실제 복구 범위와 안전성

기존 훈련에서 실제 선택된 고유 표준 행 499개를 대조했다. 355개의 null EPS를 원본과 정확히 일치하는 실제 EPS로 복구했다. 기존 nonnull EPS 99개는 그대로 두었고, 일치하는 실제 EPS가 없는 45개는 null을 유지했다. Visa의 pro forma EPS 등을 실제 기본/희석 EPS로 대체하지 않았다.

공식 companyfacts 30종목과 Disney의 과거 발행사 원본을 확보·검사했다. 각 복구는 CIK, accession, filed, form, 회계연도·분기, 시작·종료일, 기간 길이, 통화와 실제 EPS 관측의 일치를 요구한다. ID·mappedAt·비EPS 값과 그 원본 근거를 보존했다.

실제 MariaDB에서 전체 롤백 시험을 먼저 통과한 뒤, 표준 행 355개의 `eps_diluted`, `eps_unit`, `raw_json`만 수정하고 누락된 원본 EPS 355개를 추가했다. 모든 대상의 선행값을 잠금·검사한 후 단일 트랜잭션으로 반영했다. 기존 nonnull EPS나 원본을 덮어쓰지 않았다. 별도 새 읽기 전용 연결에서 355개 행의 전체 컬럼 및 355개 원본을 재확인했다.

근거:

- 불변 백업·manifest·rollback/commit 영수증: `tmp/quant-eps-live-recovery-20261101-v1/`

- 백업 SHA256: `659a1320f55d8a3567c180da05555e55a87146d99892cae27f538d786215b779`

## 3. 사전 고정한 시간순 검증

기존 알고리즘·고정 가중치·하이퍼파라미터를 변경하지 않고, 복구한 EPS만 바꾼 동일 입력으로 실제 V2–V9 모델을 재생한다. 자동 학습·보정값은 달라진 과거 입력으로 각 시점에서 다시 산정하므로 모든 학습 계수가 수치적으로 고정되어 있다는 뜻은 아니다. 과거 정답을 가린 상태에서 예측하고, 각 시점보다 엄격히 이전에 보유기간이 종료된 행만 학습한다. 같은 날 또는 미래 정답을 학습에 넣지 않는다.

- 예측일: 2017-01-31~2020-08-28, 902거래일 / 26,401행.
- 사용할 수 있는 최종 정답 종료일: 2020-09-29. 이후 가격·벤치마크는 입력 파일에서 제거했다.
- `testDecisions=[]`; 이미 시험한 60건의 정답·시험 예측 배열·평가 결과는 이번 비교/적합에 사용하지 않는다.
- 주 평가: 2018Q2~2020Q3 부분 분기, 609날짜 / 17,904행의 날짜 균등 MAE. 수익률과 시장 대비 초과수익률을 별도로 측정한다.
- 보조 평가: 전체 OOF 870날짜 / 25,473행, RMSE·편향·분기별 성과.
- 차이의 불확실성: 21개 날짜 이동블록 부트스트랩 1,000회, seed 20261101.
- EPS 효과와 가중치 효과를 분리한다. 결과 확인 전에, 이전에 고정한 후보 10개·33개 지표·패널티·분기별 nested 선택 절차를 그대로 재실행하도록 기록했다. 성과를 보고 후보를 추가하지 않는다.

현재 protocol SHA256: `d3619189eea848f46e2e2c098593c6dbe0ae057369a25cbc34cbecfbd86cec10`.
산출물: `tmp/quant-eps-v9-training-20261101-v2/`.

첫 실행 V1은 902일 계산 후 중복된 대량 출력을 하나의 문자열로 저장하다 JVM 배열 크기 한계에 걸렸다. 비교 오차는 계산하지 않았고, 실패 산출물을 덮어쓰지 않았다. V2는 출력만 스트리밍으로 바꾸고 중복을 제거했다. 모델 수식·입력·평가 규칙을 바꾼 재시도가 아니다.

902일의 실제 V2–V9 재생을 끝냈다. 총 203,784개 OOF 예측 중 V9 25,473개를 비교했다. 읽기 전용 재생의 DB 전후 행 수·재무 지문은 일치했고 쓰기는 0건이었다. 결과 파일 SHA256은 `98963fc2a3764ec52fefb2fd0bd9c980ee41de30118125235bae7f7389799088`이다.

실제 선택된 최신 연간 재무의 EPS 존재 건수는 `3,317 → 23,250 / 26,401`, 최신 분기는 `4,540 → 23,082 / 26,401`로 늘었다. 이는 모델 입력 조회 횟수이며 독립 표본 수가 아니다. 26,401개 훈련 행 중 valuation 점수 19,511개, 종합 점수 22,609개가 바뀌었다. 다른 10개 세부 점수는 모두 동일했다. 현재 역사적 점수 구현에서 EPS는 주로 PE/valuation을 통해 영향을 주고, 성장·실적 점수는 매출·순이익 비교에 기반하므로 EPS 복구만으로 이 점수들이 바뀌지는 않는다. 이 구분을 무시하고 EPS가 모든 지표를 개선했다고 주장하지 않는다.

### 동일한 10후보 절차 재검증

원래 후보·33개 지표·목적함수·패널티·10개 outer 분기·3개 이전 분기 선택 규칙을 그대로 반복했다. 복구된 후보별 결과를 본 뒤 후보를 추가하거나 패널티를 바꾸지 않았다. 기존 후보의 과거 성과는 알고 있던 상태이므로 새 블라인드 검증이라고 부르지 않는다.

RMSE도 각각 `8.305680 → 8.327522`, `6.054867 → 6.057903`으로 악화했다. 선택 절차의 미래 정답 변경 불변 테스트는 통과했지만, 정확도 개선은 없었다. 수익률 MAE가 가장 낮은 후보를 사후에 골라 승격하지 않는다. 예를 들어 단순 과거 중앙값은 MAE가 낮지만 수익률 RMSE가 더 높으며, 전체 후보를 본 뒤 선택하면 별도의 선택 편향이 생긴다.

따라서 데이터 손실 수정과 올바른 EPS 복구는 유지하되, 이번 후보 가중치·후처리는 운영에 적용하지 않는다. 후속 개선은 회계 입력의 추가 누락·가용 시점과 지표 설계를 별도로 사전 고정하고, 미노출 기간 또는 실제 전방 데이터에서 확인해야 한다. 이번 결과를 보고 같은 60건에 맞추는 방식으로 진행하지 않는다.

## 6. 해석 제한

이번 비교 구간은 이미 사용한 훈련 자료의 내부 재검증이지 새로운 미사용 시험이 아니다. 고정 과거 모집단의 생존 편향, 겹치는 20거래일 정답, 비EPS 입력 누락, 현재 취득한 원본의 PIT 한계가 남는다. 행 수를 독립 표본 수로 해석하지 않는다. EPS 복구가 정확하다는 사실만으로 미래 예측력이 개선되었다고 결론내리지 않는다. 운영 가중치 승격은 별도 미노출 기간 또는 실제 전방 검증 근거가 필요하다.

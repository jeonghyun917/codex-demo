# 동결한 후보를 만기 후 평가하는 일일 경로를 연결했다

기존 V9와 후보의 실제 20D 오차를 같은 기준으로 비교할 수 있도록 평가기를 연결했다. **현재는 만기 전이므로 예측력 개선 여부는 여전히 미확정**이다. 기존 모델·가중치·629개 전방 예측은 바꾸지 않았고, 이미 끝난 전체 백테스트도 반복하지 않았다.

## 실행된 변경

- 기존 일일 컨트롤러가 수집한 동일 종가 파일로 기준 V9 평가와 후보 평가를 따로 기록한다. 후보 30개를 기존 629개에 더해 새로운 독립 표본처럼 집계하지 않는다.
- 원래 DOW30 저장 벤치마크 프록시, 2026-11-02 진입·2026-12-01 청산, 동결된 모든 30종목과 두 후보를 그대로 사용한다. 재학습·후보 선택·승격 기능은 없다.
- 거래소 달력의 실제 청산 종가 시각 전에는 오차·실현 수익률을 내지 않는다. 이후에도 21개 종가 중 하나라도 빠지면 전체 후보 코호트의 MAE/RMSE/편향과 차이값을 null로 유지한다. 완전한 일부 종목만으로 유리한 점수를 발표하지 않는다.
- 완전한 만기 자료가 모이면 수익률과 산술 초과수익률의 MAE·RMSE·편향, 같은 종목의 기준 대비 차이, 항상 0% 예측 참조를 계산한다. 기존 평가 방식과 대상은 변경하지 않았다.
- 후보 파일이 변조되거나 출처·날짜·모집단이 맞지 않으면 별도 실패 영수증과 `FAILED_CANDIDATE_EVALUATION`, CLI 오류 종료 코드로 드러난다. 기존 기준 평가 결과는 따로 남긴다.

새 평가용 묶음은 `data/quant-candidate-evaluation-20261101-v1/DOW30/bundle.json`이다. 원래 출처 14개의 바이트와 해시를 함께 보존하여 임시 연구 코드·클래스 파일이 없어져도 **종가 입력이 있을 때 오프라인 평가**할 수 있다. 이는 새 예측 생성이 아니라 이미 동결한 자료의 복사·보존이다. 원래 후보 프로토콜과 예측 파일은 수정하지 않았다. 두 후보 중 과거 오차 기반 혼합은 비중 0이라 기준과 동일하고, 절반 완화 후보는 이전 내부 초과수익률 오차를 키웠다는 한계도 그대로다.

## 실제 일일 실행 점검

2026-11-01 13:52 UTC 실행 전에 세 지수가 모두 기존 동결 상태이고 가격 수집·예측 생성이 필요 없음을 확인했다. 실제 실행 영수증:

기존 일일 실행이 이 컨트롤러를 호출하면 후보 평가도 함께 진행한다. 새로운 앱 자동화나 스케줄을 추가하지 않았다. PC·Codex·로컬 DB가 실행 중이어야 한다는 기존 조건은 같다. 만기 예정은 미국장 12월 1일 종가이며 한국시간으로는 **12월 2일 오전 6시 이후**, 정확한 종가 자료까지 확보돼야 평가할 수 있다.

## 남은 원문에서도 추가 근거를 찾았다

### GS: 원공시와 SEC 재구성 API의 기간이 달랐다

캐시된 동일 공시의 원래 XBRL은 `ThreeMonthsEnded_30Jun2013` 문맥에 **2013-04-01~2013-06-30, 91일**을 사용한다. 같은 무차원 USD 문맥에 매출 8,612백만 달러·순이익 1,931백만 달러·희석 EPS 3.70달러가 있고, 연결 손익계산서 표에서도 확인됐다. 영업이익은 없으므로 세전이익으로 대체하지 않았다.

반면 현재 SEC companyfacts 캐시는 해당 순익·EPS를 3월 31일 시작으로 제공한다. 기존 연구 행은 이 날짜를 그대로 계승했다. 원공시 날짜 오류나 프로젝트의 날짜 뺄셈이 원인이라고 볼 근거는 없고, API 내부 재구성 원인은 확인하지 못했다.

정확한 4월 1일 시작 행을 **별도 연구 후보**로 보존했다. 기존 3월 31일 행을 조용히 바꾸거나 잘못된 키에 매출을 넣지 않았으며, DB·기존 모델에는 반영하지 않았다.

근거: `tmp/quant-gs-period-reconciliation-20261101-v1/`의 `canonical-research-rows.json`, 원문·API 비교, 검증 기록.

### AMGN: 다른 공식 분기 발표에는 연결 총매출이 있었다

Amgen 공식 실적발표 원문 7개에서 제품 매출·기타 매출과 구분된 **GAAP 연결 총매출**을 직접 확인했다.

| Q4 연도 | 연결 총매출(USD 백만) | 원문 발표일 |
|---|---:|---|
| 2013 | 5,011 | 2014-01-28 |
| 2014 | 5,331 | 2015-01-27 |
| 2015 | 5,536 | 2016-01-28 |
| 2016 | 5,965 | 2017-02-02 |
| 2017 | 5,802 | 2018-02-01 |
| 2018 | 6,230 | 2019-01-29 |
| 2019 | 6,197 | 2020-01-30 |

각 원래 발표의 해당 연도 열만 사용했고, 발표일은 연결된 13개 10-K 대상의 공시일보다 앞선다. 그러나 같은 accession이라는 증거는 없으므로 기존 10-K 대상에 덮어쓸 수 있는 자료로 처리하지 않았다. 원문은 “12월 31일 종료 3개월”을 명시하며 10월 1일 시작은 그 기간의 달력 경계라는 점도 구분했다.

독립적인 발행사 원문 분기 후보 7개와 기존 대상 13개와의 관계를 보존했다. 현재 **기존 누락 집계는 189/203 복구·14개 미반영 그대로**다. 새 근거를 실제 모델에 사용하려면 출처가 다른 분기 자료 및 원공시 우선 날짜를 정확히 정규화하는 별도 검증이 필요하다. 이번 작업에서 성능이 좋아졌다고 주장하거나 재생 결과를 만들지 않았다.

근거: `tmp/quant-amgn-quarter-originals-20261101-v1/`의 `source-quarter-candidates.json`, `target-associations.json`, 원문·발표일·단위·해시 검증. 수집은 무료 공식 원문만 사용했고 이전에 차단된 SEC 경로를 재시도하거나 우회하지 않았다.

## 검증과 남은 조건

- 새 평가기 9개·일일 연결 3개 테스트를 RED→GREEN으로 확인했다. 만기 전 미래 가격 제공, 중간 종가 누락, 원본 삭제 후 묶음 평가, 변조, 잘못된 지수, 고정 분모, 영구 출력 덮어쓰기 방지를 포함한다.
- 전체 Python 테스트는 scripts 280개, tests/python 43개가 통과했다. 애플리케이션 Java 모델 변경이 없으므로 무관한 전체 Maven·모델 재생을 반복하지 않았다.
- 독립 검토는 14개 묶음 해시, 같은 30개 분모·원래 거래 달력·프록시, 오차 계산·실패 처리, GS 원문 문맥 및 AMGN 7개 표를 확인했다. Critical/Important 구현 결함은 없었다. Minor 중 RMSE·편향 리터럴 검사는 최종 전체 테스트 전에 추가됐고, pending 상태의 모든 zero/paired-null 필드를 직접 나열하는 추가 검사는 비차단 후속으로 남겼다.
- 이 결과는 **평가 자동 경로의 준비 완료**이지 실제 예측 오차 개선이나 미사용 과거 검증의 완료가 아니다. 기존 60건 시험 정답은 열거나 학습에 쓰지 않았다. 실제 만기·가격 완전성 확인 전에는 결과를 발표하지 않는다.

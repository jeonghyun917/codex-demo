# 모의운용 페이지: 데이터에서 투자 후보까지

## 목표와 제한

과거 데이터와 실제 저장한 예측으로 비용 후 투자 성과를 검증하고,
근거가 있는 관심 종목과 제외 사유를 먼저 제시한다.
최고 이윤을 보장하지 않는다. 오차 감소, 매매 성과 개선, 데이터 정합성 개선은 별개다.
실제 운영 전략의 자동 변경이나 실제 주문은 이 연구 흐름에 포함하지 않는다.

## 우선순위와 진행 상태 (2026-11-17)

최종 목표는 다음 거래일 진입 후 최대20거래일 안에 -5%보다 +15%에 먼저
도달할 가능성이 높은 S&P500 후보를 검증된 근거로 선별하는 것이다.
확률순 관심 TOP20과 필터 통과 매수 후보, 실제 모의 계좌는 별개다.

### P0: 관찰 신뢰성 (구현·검증 완료)

- `scripts/sp500_readiness_audit.py`: 봉인된 원장과 검증된 발행 파일을 읽어
  누락 판단일, 아직 개장 전인 저장 대기일, 묶음별 만기와 평가 가능 여부를 점검한다.
- `scripts/paper_view_publication_guard.py`: 추적 기준일 후퇴, 저장 예측 변경,
  판단일 삭제, 계좌 기록 후퇴를 화면 발행 전에 거절한다.
- 11월16일 종가 기준: 저장 판단일2개, 과거 누락9개, 최신11월16일 저장 대기1개.
  누락 판단일은 11월2~6일 및9~12일이다. 당시 저장한 전방 예측으로 소급 위장하지 않는다.
- 10월30일 묶음은11/20거래일, 11월13일 묶음은1/20거래일 관찰했다.
  고정 관찰 종료 예정일은 각각11월30일,12월14일(미국 거래일)이다.
- 만기 묶음0개: 조기 종료20건을 전체40건의 대표 적중률로 사용하지 않는다.
  현재 모델 개선·승격 근거는 불충분하다.
- 결과 파일: `output/sp500-readiness-20261117/report.json` (로컬 실행 자료, Git 제외).

### P1: 일별 예측 누락 방지 (실행·복구 구현, 예외 재사용은 남음)

2026-11-17 후속 실행에서 전체503개 최신 일봉을 검증하고 11월16일 판단 예측을
다음 개장 전에 저장했다. 저장 판단일은3개가 되었으며 과거 누락9개는 소급 채우지 않았다.
495개 분석·매수 조건 통과0개·관심TOP20 발행을 확인했다.
일별 명령, 단계별 재개, DB 발행 직후 중단 복구와 반복 실행 검증을 완료했다.
운영 방법과 남은 예외는 `docs/sp500-paper-daily-operations.md`를 참조한다.
사용자 승인에 따라 새 `Quant 일별 예측·복구` 예약을 화~토07:30/21:30 KST로 등록했다.
삭제된 `v9` 예약을 복원한 것은 아니다.

1. 기존 수집 상태와 잠금을 읽고 재사용 가능한 일봉을 우선 이용한다.
2. 최신 완료 거래일의 당시 전체 구성종목·지수·품질 검사를 통과한 후에만
   원래 모델로 예측한다. TOP20 추적용21종목 가격만으로 전체 순위·변동성 임계값을 재계산하지 않는다.
3. 다음 개장 전 예측과 입력/모델 해시를 저장하고, 개장 이후에는 과거 예측을 소급 생성하지 않는다.
4. 추적 갱신과 원장 평가를 분리하고 입력/출력 해시, 기준일, 누락 종목, 실패 상태를 남긴다.
5. 중단 후 수집 재실행 없이 검증된 준비 파일의 발행만 재개한다.
   `sp500_paper_daily.py --out <기존폴더> --stage publish`로 복구한다.
6. 새 예약은 위의 명시적 사용자 승인을 따른다. 기존 수집과의 중복 및 삭제된 예약 복원은 금지한다.

### P2: 확률의 실제 의미 검증 (만기·자료 확보 후)

- 전체 예측군, 관심TOP20, 필터통과군, 실제 모의 체결군의 분모를 각각 기록한다.
  TOP20만으로 전체 모델의 보정 정확도를 결론내리지 않는다.
- 미완료·누락·가격 기준 불일치를 손절/실패/0%로 치환하지 않는다.
- 완전 관찰된 판단일 묶음만으로 Brier/log loss, 확률 구간별 익절률과 불확실성을 계산한다.
  날짜·반복 종목의 상관을 고려한 날짜 블록 검증을 사용한다.
- 금액 성과는 다음 시가, 갭, 동일 일봉 양쪽 도달, 기존 자금배분,
  편도10/20bp 비용을 반영한 계좌 수익률·최대낙폭으로 별도 평가한다.

### P3: 별도 개선안 검증 (운영 미적용)

- 실험A: 확률 재보정. 과거 만기 라벨만으로 보정하고 이후 고정 구간에서 Brier/log loss를 비교한다.
  단조 보정의 확률 신뢰도 개선을 매매 수익 개선으로 표현하지 않는다.
- 실험B: 손절·기간청산·비용을 반영한 기대수익 순위. 기존 모델·필터·배분을 대조군으로 두고,
  동일 시점/종목/가격에서 별도 파일형 계좌로 비교한다. 운영 원장에는 기록하지 않는다.
- 기간 분할과 비교 후보를 결과 열람 전에 고정한다. 20거래일 미래 라벨이
  학습/평가 경계를 넘지 않도록 제거하고, 평가 기간으로 임계값을 반복 조정하지 않는다.
- 비용 후 수익률, 최대낙폭, 거래 수, 현금 비중, 손실 꼬리와 기간별 안정성을 함께 공개한다.
  최소126개의 만기 판단일과6개의 비중첩20거래일 구간을 연구 검토의 최소 자료 요건으로 삼되,
  이것만으로 통계적 확실성이나 승격을 보장하지 않는다. 불확실성이 크면 보류한다.
- 현재는 성숙한 전방 자료 부족으로 두 실험의 새 학습·성과 비교를 실행하지 않았다.

## 과거 연결 상태 기록 (2026-11-01, 아래는 당시 상태)

최신 전체 재생 요청의 입력 감사는 `docs/sp500-v9-full-replay-status-2026-11-01.md` 참조.
후속 무료 원문 보완 결과는 `docs/sp500-v9-source-recovery-2026-11-01.md` 참조.
잔여55종목의 13,052행 모두에 판단일 이전 공시를 연결했다. 다만 클래스 권리와
가격·EPS·주식수 기준이 미확정이어서 전체 V9 생성/계좌 비교는 아직 실행하지 못했다.
원문 연결 충족과 모델 투입 승인을 구분하고 기존 부분 비교를 전체 비교로 반복 게시하지 않는다.

`docs/sp500-v9-shadow-results-2026-11-01.md` 참조.
보관 V9의 제한된 교집합 비교만 완료. 최신 EPS 복구 V9와 S&P500 일별 공통 패널은 아직 없음.
데이터가 없는 부분은 예측 재사용이나 중립값으로 채우지 않는다.
실제 모의운용과 연구 실험의 자산/수익률/버전/분모를 합치지 않는다.

## 발전 순서

1. 예측 원장을 먼저 연결한다. V9, 기존 확률, 연구 기대수익률을 같은 판단일/종목 키로
   저장하되 모델·입력 해시와 실제 저장시각을 구분한다. 다음 시가 이후 저장은 주문 불가다.
   생산 원장은 기존 상태를 유지하고 별도의 shadow 저장소에서 시작한다.
2. 동일한 전체 후보군·날짜·현금·비용의 일별 계좌 비교를 확보한다.
   전체/교집합/모델 누락을 구분하고 빈 구간을 수익률 0 또는 성능 개선으로 오인하지 않는다.
3. 페이지는 '관심 후보와 제외 사유 → 검증된 근거 → 실제 모의 성과' 순서를 유지한다.
   후보에는 데이터 기준일, 모델 버전, V9 수익률 예측, 배리어 익절 확률을 서로 다른 지표로 표시한다.
   비용 후 거래 기대수익률은 그 목표에 맞춰 학습·검증한 경우에만 그 이름을 쓴다.
4. 모델 비교 영역은 '연구 전용/전방 검증 중/검증 부족'을 표시하고,
   현금 포함 수익률·최대낙폭·거래수·현금 비중·비용 민감도·기간/종목 범위를 함께 보여준다.
   순위 하나로 강한 매수 추천을 단정하거나 소표본 수익만 강조하지 않는다.
5. 신규 미사용 기간과 실제 만기 결과가 축적된 후에만 후보 승격을 검토한다.
   주 지표는 비용 후 전체 자금 수익률, 손실 관리는 낙폭과 큰 갭 손실,
   안정성은 여러 기간/종목/비용 시나리오다. 과거 최고값 탐색으로 대체하지 않는다.

위 항목은 발전 기준과 후속 작업이며, 현재 웹 페이지에 구현됐다는 뜻이 아니다.

## 과거 자동화 기록 (현재 비활성)

자동화 `v9`는 사용자 요청으로 삭제되었다. 아래는 당시 설계 기록이며 실행 중이라는 뜻이 아니다.
당시 자동화 `v9` (V9·모의운용 연구 연결 점검)는 한국시간 매일16:10에 이 채팅에 연결했다.
기존15:10 데이터 수집 자동화와 별개로 완료된 연구 및 저장 예측의 새 증거를 확인한다.
수집/DB 작업을 중복하지 않으며, 변경 없는 입력의 재실험은 하지 않는다.
운영 DB·원장·주문·모델·사이트·Git 자동 수정은 금지한다.
유의미한 결과 변화, 신규 장애, 필요한 결정이 있을 때만 보고한다.
로컬 Codex/PC가 실행 가능해야 하며 예약 생성은 실행 성공 증거가 아니다.

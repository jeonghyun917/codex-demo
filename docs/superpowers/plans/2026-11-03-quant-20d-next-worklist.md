# Quant 20D 후속 작업 목록

**목표:** 이미 보지 않은 실제 20거래일 예측 오차를 줄이는 모델을 검증하고, 그 모델을 재현 가능한 제품 경로로 연결한다.

**근거:** [전체 검수 보고서](../../quant-full-work-audit-2026-11-03.md).

**실행 갱신:** [1–12 실행 결과와 남은 실제 게이트](../../quant-20d-execution-results-2026-11-03.md). 1–6 운영 안전/입력 대조와 11–12 로컬 통합을 진행했다. 7은 source-aware dry-run까지, 8은 전역 노출 UNKNOWN으로 신규 미사용 구간 미인증, 9는 비활성 미래 프로토콜 준비, 10은 실제 만기 대기다. 아래 원래 체크박스는 승인 당시 백로그를 보존한 것이며 모든 성능 조건의 완료를 뜻하지 않는다.

**문서 범위:** 우선순위·의존성·산출물·완료 기준을 정한 실행 백로그다. 아직 구현하지 않은 항목은 모두 미완료다. 각 항목에 착수할 때 필요한 함수/스키마/테스트 변경만 구체화하며, 이 목록을 전체 작업의 완료나 DB 변경 승인 영수증으로 해석하지 않는다.

**구조:** 기존 Java21/Spring Boot/MariaDB/MyBatis 제품과 Python 연구·전방 평가 경로를 유지한다. 기존 동결 예측·프로토콜·원문은 보존하고 새 코드/자료/실험은 별도 버전으로 연결한다. 새 예측 생성, 기존 예측의 정답 수집, 자료 품질 수정, 모델 성능 개선을 서로 다른 결과로 기록한다.

## 공통 제약

- 기존에 시험한 60건으로 지표·가중치를 다시 맞추지 않는다. 미사용 자격 확인은 노출 메타데이터부터 한다.
- 현재 동결된 1,257개 기준 관측과 별도 DOW30 후보 30개의 값·대상·벤치마크·진입/청산일을 소급 변경하지 않는다.
- 기존 전방 프로토콜의 선택적 역사 기준선은 null 그대로다. 과거 중앙값 등 새 기준선을 기존 코호트에 사전 동결한 것처럼 덧붙이지 않는다.
- 0%·기존 V9·사전에 고정한 단순 참조와 같은 표본/타깃으로 비교한다. 일부 MAE 감소만으로 승격하지 않는다.
- 무료 공식/원문 근거를 우선한다. 403/429/인증 차단은 중단하며 재시도·우회로 해결하지 않는다.
- 운영 DB 반영은 preimage·백업·드리프트 검사·rollback·postimage 대조를 갖춘 별도 단계다. 연구 파일을 그대로 복사하지 않는다.
- 페이지 요청은 DB 읽기 경로로 유지한다. 새 외부 수집·전체 모델 재생을 GET 안에 넣지 않는다.
- main/현재 dirty 변경과 무관 파일을 보존한다. 커밋·Push·병합·배포는 별도 명시 요청과 해당 단계의 검증 근거로 관리한다.
- 검증은 변경 위험에 비례한다. 같은 코드·입력 해시의 테스트/백테스트를 이동·문서화 때문에 반복하지 않는다.

## A. 바로 착수할 운영 안전 작업

### 1. 현재 기준선·원문·예측의 안전한 보존

- [ ] 기존 자료 위치, 코드/입력 해시, 기준 V9와 고정 후보, 동결 예측, DB 복구 영수증을 하나의 보존 목록으로 연결한다.
- [ ] 무관 파일과 구현 변경을 구분하고, 로컬 전용 데이터/비밀정보를 코드 배포 대상과 분리한다. 기존 원본은 이동·정리·삭제하지 않는다.
- **완료 기준:** 재시작 후 같은 기준과 예측을 찾고 해시를 검증할 수 있으며, 데이터 손실 없는 별도 보존/복구 방법이 명시돼 있다. 자동 원격 전송·커밋은 하지 않는다.
- **의존성:** 없음. 이후 모든 변경 전에 기준 보존.

### 2. 기존 예측의 정답 수집을 새 예측 생성과 분리

- [ ] 새 20D 예측을 만들 수 없는 달력 경계에서도 기존 동결 종목의 종가·벤치마크를 계속 확보한다.
- [ ] 공식 달력 연장, provider 차단, 중복 실행, 부분 실패, 기존 이름 유지 경로를 검사한다.
- **주요 경로:** `scripts/quant_daily_forward.py`, `scripts/QuantStartForwardCollection.java`, 기존 전방 테스트.
- **완료 기준:** 새 예측은 차단된 합성 달력에서도 기존 코호트 정답 유지가 작동하고, 실제 알려진 거래일만 사용한다. 현재 달력의 12월 2일 경계 전에 대비한다.
- **의존성:** 1. 과거 가중치 탐색이나 만기 대기 없이 구현 가능.

### 3. 동결 대상과 성공한 실행 영수증의 결합

- [ ] run ID·사전 적격 명단·실제 예측·미예측 사유·모델 완료 영수증을 연결한다.
- [ ] 부분 모델 출력이나 실패 실행이 남긴 archive가 조용히 정상 코호트로 동결되지 않게 한다.
- **주요 경로:** `scripts/QuantStartForwardCollection.java`, `scripts/quant_daily_forward.py`, `scripts/quant_forward_validation.py`.
- **완료 기준:** 사전 명단과 최종 예측/명시적 미예측이 정확히 대조되며, 불완전 실행은 명시적으로 거절하거나 검토된 복구만 허용한다. 기존 코호트는 재동결하지 않는다.
- **의존성:** 1. 2와 통합 동작 검증.

### 4. 거래 종료·합병·진입 불가·가격 누락 분리

- [ ] KVUE의 진입 불가를 별도 진단으로 표시하고, 거래 종료와 일시적인 수집 실패를 구분한다.
- [ ] 기준 평가의 일부 완전 종목 점수와 후보 평가의 전체 30종목 조건을 명확히 표시한다.
- **주요 경로:** 전방 진단/보고 단계, 기존 평가기는 원래 계약 유지.
- **완료 기준:** 원래 분모·예측을 보존한 채 사유가 노출된다. 전일 종가·합병 대가·KMB를 가짜 KVUE 종가로 대체하지 않으며 일부 표본 점수를 전체 성과로 부르지 않는다.
- **의존성:** 1, 3. 새로 취득한 기업행사 근거를 과거에 알고 있던 정보로 소급하지 않는다.

### 5. 새 전방 예측의 입력·계산 근거 보존

- [ ] 향후 코호트부터 실제 사용 특징값, 선택 원천/기간/단위, 가용성 시각, 모델/보정 cutoff, 코드·입력 해시를 연결한다.
- [ ] 예측 발표 시각과 입력이 시장에 공개된 시각, 시스템이 취득한 시각을 구분한다.
- **완료 기준:** 한 종목의 예측이 어떤 입력에서 나왔는지 재현 가능하며, 이전 동결 출력에 뒤늦게 자료를 붙여 완전 PIT라고 주장하지 않는다.
- **의존성:** 3. 필요한 저장량과 새 버전 경계는 착수 시 설계하고 불필요한 전체 원천 복제를 기본으로 삼지 않는다.

## B. 만기를 기다리는 동안 진행할 자료·연구 작업

### 6. 연구 입력과 운영 as-of 입력의 차이 목록

- [ ] 같은 종목·판단일·공시·기간·통화·필드에 대해 연구팩과 실제 제품 조회를 대조한다.
- [ ] 일치/불일치/미확보와 예측 입력에 미치는 범위를 구분한다. 189개 매출 복구가 운영 반영 완료라는 가정은 하지 않는다.
- **산출물:** 입력 경로별 parity 보고서와 필요한 수정/반영 목록.
- **완료 기준:** 차이의 원인과 영향이 설명되고, 미확보 입력을 중립 점수나 추정값으로 감추지 않는다. DB 반영은 다음 항목의 근거와 별도 검증 후 수행한다.
- **의존성:** 1. 운영 안전 작업과 독립적인 읽기 전용 대조는 병행 가능.

### 7. AMGN·GS 및 필요한 추가 원문의 정규화·안전한 반영

- [ ] AMGN 원문 7개와 기존 13개 대상은 출처가 다른 분기 자료로 연결한다. 같은 accession이라고 꾸미지 않는다.
- [ ] GS의 원공시 기간과 API 기간 충돌을 새 버전으로 설명하고, 기존 봉인 키를 조용히 바꾸지 않는다.
- [ ] 필요성이 입증된 나머지 공시·IFRS/ADR·주식 종류 자료를 우선 보완한다. 수집 건수만 늘리는 탐색은 하지 않는다.
- **완료 기준:** 원문·발표일·정확 기간·단위·선택 필드의 근거를 추적할 수 있다. 운영 반영 시 새 버전·백업·rollback·후검산과 새 예측의 데이터 버전이 남는다.
- **의존성:** 6의 차이 목록. 원래 누락 203개 분모는 계속 추적하며 별도 출처 후보를 정확한 기존 키 복구 수와 섞지 않는다.

### 8. 진짜 미사용 과거 구간의 자격 확인

- [ ] 기존 5D/20D/60D 노출 장부를 메타데이터로 합치고, 미확인 노출을 보수적으로 구분한다.
- [ ] 후보 구간의 당시 구성종목·기업행사·주식수/종류·재무·업종·훈련 종료일을 확인한다.
- **완료 기준:** 새 정답을 보기 전에 사용 가능한 구간과 사전 학습/선택 규칙을 동결한다. 인증할 수 없으면 미사용 검증으로 부르지 않고 전방 수집을 유지한다.
- **의존성:** 필요한 입력은 6–7. 2017년 이후 학습 모델을 더 옛날에 적용하거나 최소 모집단 제한을 낮춰 과거 검증을 만든 것으로 세지 않는다.

### 9. 지표·가중치 개선 후보의 제한된 설계·시간순 시험

- [ ] 시장 공통 오차·고변동성·특징 누락과 기존 V6–V9 보정 경로를 구분해 가설을 제한한다. 이미 설명한 원인을 재발견하는 실험은 피한다.
- [ ] 후보 수·주 지표·실질적 개선 기준·선택 규칙을 먼저 고정하고, 0%/기존 V9/과거 성숙 중앙값 등 단순 참조를 포함한다.
- [ ] 기존 노출 구간의 탐색 결과와 8의 미사용 시험 또는 새 전방 시험을 분리한다.
- **완료 기준:** 같은 표본에서 두 MAE와 RMSE·편향·커버리지·고변동성 손상을 함께 판정한다. 결과를 보고 후보를 추가하거나 이름만 다른 동일 예측을 개선 모델로 세지 않는다.
- **의존성:** 6의 원인 확인과 시험 입력. 새 성능 주장은 8 또는 사전 동결 전방 근거가 있어야 한다.

## C. 시간을 기다려야 완료할 수 있는 검증

### 10. 기존 코호트 만기 평가와 추가 날짜 축적

- [ ] 기존 예측 그대로 종목·벤치마크의 21개 종가 완전성, 진입 불가, 원래 분모와 누락을 확인한다.
- [ ] 최초 코호트는 한국시간 **2026-12-02 06:00 이후**, 두 번째는 **12-03 06:00 이후** 종가 확보 상태에 따라 평가한다. 이는 완료 보장 시각이 아니라 가장 이른 판정 가능 시각이다.
- [ ] 양 오차·RMSE·편향·기준 대비 차이를 발표하고, 지수·코호트·20D 창의 중복을 독립 표본으로 세지 않는다.
- **완료 기준:** 원래 프로토콜을 지킨 실제 평가와 적격/누락 수가 남는다. 한 코호트만으로 안정적인 개선을 선언하지 않고 여러 날짜 블록·국면을 추가 축적한다. 새 참조 예측은 향후 코호트의 진입 전에만 새 버전으로 동결한다.
- **의존성:** 2–5의 운영 보완과 실제 시간·가격 가용성. 후보가 실패하면 기준 유지.

## D. 제품 완성·전달

### 11. 결과 화면과 백테스트 해석 통합

- [ ] 연구 결과·실제 전방 결과·운영 모델을 구분하고, MAE/기준선/기준일/누락/만기 대기를 DB 기반으로 표시한다.
- [ ] 비중첩 자본 회계, 비용, 배당 제외, 거래 종료 및 청산가 한계를 드러내고 수익률 예측 오차와 전략 수익을 구분한다.
- [ ] 서버 가동 후 desktop/mobile, 첫 요청 지연, 조회 중 외부 수집/모델 재생이 없는지 확인한다.
- **완료 기준:** 파일 연구가 끝났다는 사실과 실제 검증·승격 상태를 화면에서 혼동하지 않는다. 기본값·null·0·자료 부족이 구분된다. 만기 전 점수나 투자 수익을 만들어 표시하지 않는다.
- **의존성:** 4–6의 상태/근거 정의. UI 틀은 먼저 만들 수 있고 실제 성과 표시는 10 이후.

### 12. 최종 회귀·저장·승격·배포

- [ ] 변경된 금융 로직·API·수집/실패 경로를 자동 검증하고, DB 위험 변경은 별도 fixture/rollback 근거로 확인한다. skip을 통과로 세지 않는다.
- [ ] 검증된 코드·자료·프로토콜·증거를 버전으로 연결하고 재시작/복구 가능 여부를 확인한다.
- [ ] 성능 기준을 실제로 통과한 후보만 별도 승격한다. 데이터 정확성 수정과 성능 보정 승격을 구분한다.
- **완료 기준:** 해당 버전의 근거가 있는 통합 결과와 안전한 복구 방법이 있다. 개선 실패 시 모델 교체 없이 실패/대기를 보고한다. 명시적인 커밋·Push·배포 요청 없이 원격 전송하지 않는다.
- **의존성:** 변경 범위에 따른 1–11. 개선 모델 승격은 반드시 9–10 근거 이후이며, 기반 안전 수정의 저장/배포는 승격을 기다릴 필요가 없다.

## 실행 순서와 중단 기준

- 기본 순서: **1 → 2 → 3 → 4 → 5**, 그동안 읽기 전용 **6 → 7 → 8** 준비를 병행할 수 있다. 이후 **9 → 10 → 11 → 12**로 이어간다.
- 10의 시간 대기는 다른 구현/자료 준비를 막지 않는다. 반대로 기다릴 수 없다는 이유로 과거 시험을 재사용하거나 만기 전 점수를 만들지 않는다.
- 자료가 막히면 부족한 근거와 영향만 기록하고 독립적인 작업을 진행한다. 같은 입력의 모델 재생을 반복하지 않는다.
- 이 목록에서는 소요 시간을 임의로 약속하지 않는다. 변경별 검증은 필요한 범위만 한 번 수행하고, 중요한 실제 결함이 아니면 추가 정밀 감사를 반복하지 않는다.
- 이 문서를 만든 시점에는 위 12개 후속 항목을 구현하지 않았다. 완료한 기존 수리는 전체 검수 보고서에서 확인하고 중복 수행하지 않는다.

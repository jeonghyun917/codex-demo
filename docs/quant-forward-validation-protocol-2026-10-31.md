# Prospective saved-output validation protocol — 2026-10-31

Status: preparation only. No real future observation, matured outcome, predictive improvement, or promotion is claimed by this document. The synthetic unit tests are not empirical model evidence. No application/UI setting, database row, scheduler, or automation is changed by this workflow.

## Frozen contract

The stdlib-only `scripts/quant_forward_validation.py` has three offline commands: `init`, `freeze`, and `evaluate`. Every output is create-only; an existing filename causes failure. Input bytes for the exchange calendar, every scanned archive, and evaluation prices are SHA-256 identified. The full protocol, fixed baseline values if supplied, exact prediction objects, and embedded calendar participate in canonical content hashes. A report references the frozen manifest content hash; the manifest embeds the hashed protocol.

1. `init` records the actual execution timestamp. There is no CLI backdating option. Only archives captured at or after this timestamp can qualify. Initialize before collecting prospective observations, not after seeing their outcomes.
2. Supply an explicitly sourced exchange-session calendar CSV with `session,openUtc,closeUtc`. Each row is a real session label and timezone-aware opening/closing instant. Rows must be unique, chronological, and nonoverlapping. Include the previous closed session and at least entry plus 20 future sessions. Holiday omissions, DST transitions, and early closes come from this calendar, never weekdays, the UTC date, server locale, or inferred NY offsets. Retain the source calendar evidence alongside the hashed CSV. The script checks consistency, not exchange authenticity or completeness.
3. V2 binds each protocol's explicit `indexCode` to its benchmark symbol. `init --index-code` defaults to `SP500` and must be changed when preparing another index. Wrong-index archives are recorded with `INDEX_BENCHMARK_MISMATCH`, even when scanning a parent archive directory containing all three indices; their forecasts cannot enter that protocol's cohort. Evaluation independently rejects a cohort whose index differs from the protocol. Use a separate protocol per index and a genuinely matching benchmark series. Benchmark closes must use those same session labels, not a constituent-availability-dependent benchmark assembled afterward. Older V1 preparations without an index binding must be preserved and superseded by a new immutable initialization, not edited in place or retrofitted onto existing observations.
4. For each archive capture, the anchor is the latest exchange session whose close is at or before `capturedAtUtc`. Entry is the immediately following session's close; exit is **20 sessions after entry**. This requires 21 close observations from entry through exit. It matches next-session-close to entry-plus-20-session-close, not signal-close to 20 observations later.
5. Capture **and cohort freeze** must be strictly before entry close. An observation arriving exactly at an exchange close anchors to that just-closed session and enters the following session. Intraday and weekend captures therefore align without trusting server-local `signalDate`. The original signal date remains in the manifest for audit; its freshness and intended training target are not established by this realignment.
6. Within an index/anchor, select the earliest eligible capture, irrespective of future price availability, and retain **all** its saved prediction rows. Later/exact duplicate captures are recorded as excluded. Conflicting predictions with identical capture timestamps fail instead of choosing opportunistically. Duplicate symbols within a cohort fail. `predictions` is the current Java archive key; `predictionsV9` is also accepted. Rows must have a 20-session horizon, `LIVE_V9_` source, and the archive's model version.
7. Archives preceding protocol creation, following freeze time, or frozen after entry cutoff remain accounted for with explicit exclusion reasons; they are never relabeled historical LIVE validation. Malformed eligible archives fail visibly. Insufficient calendar coverage fails rather than dropping an observation or inventing a session.
8. `evaluate` does not accept a future `--as-of`. Outcomes are `PENDING_OUTCOME` until the scheduled exit close, even if a CSV already contains future rows. Once that close passes, missing any of the 21 held-symbol or benchmark closes yields `INSUFFICIENT_PRICES`, not a dropped name or a forward-filled value. This includes suspended/delisted/missing securities; complete-case MAE must not be mistaken for whole-cohort performance.
9. Absolute return is `100 * (exitClose / entryClose - 1)`. Excess return is that absolute return minus the benchmark's matching entry-to-exit return, in percentage points. Metrics compare saved `expectedReturnPct` and `expectedExcessReturnPct` respectively, without re-estimation. MAE is equal-weighted across mature observations with the corresponding non-null saved prediction. ZERO uses the identical scored pairs. An optional historical baseline is fixed at protocol initialization, with declared training ending strictly before protocol start; no baseline is fitted on prospective outcomes.
10. Reports include total frozen observations, every per-symbol status, missing held prices, and per-target scored `n`. MAE is null when no eligible pairs mature. A missing saved target cannot silently become a zero forecast: it remains null and does not count toward that target's scored `n`. A symbol can appear across separate anchor sessions; therefore the equal-observation errors are overlapping, not independent samples or confidence intervals.

## Files and manual commands

Run from the repository root. Substitute actual evidence paths and create the destination parent directory first. The prepared calendar is `scripts/data/quant-forward-calendar-20261030-20261231.csv` (43 scheduled sessions); its adjacent `.source.json` records a curated transcription of the [NYSE calendar](https://www.nyse.com/trade/hours-calendars) and [Nasdaq calendar](https://nasdaqtrader.com/Trader.aspx?id=Calendar) verified by the parent task. It excludes November 26/December 25 and closes at 13:00 ET on November 27/December 24, with explicit DST-adjusted UTC instants. Raw original source responses were not archived. The following are templates, not commands executed to manufacture observations:

```powershell
python scripts/quant_forward_validation.py init --calendar scripts/data/quant-forward-calendar-20261030-20261231.csv --index-code SP500 --benchmark-symbol EXPLICIT_STORED_BENCHMARK_SP500 --out path/to/protocol.json
python scripts/quant_forward_validation.py freeze --protocol path/to/protocol.json --archive path/to/quant-forward/SP500 --out path/to/cohort-before-entry.json
python scripts/quant_forward_validation.py evaluate --manifest path/to/cohort-before-entry.json --prices path/to/verified-close-prices.csv --out path/to/evaluation-asof-now.json
```

To freeze a different future entry cohort, write a new manifest **before that entry's close**. Old, already-entered archives will be explicitly excluded. Preserve earlier manifests; evaluate each unchanged as its outcomes mature. Repeated evaluation uses new output filenames, not replacement. No background job or recurring automation is installed.

The price CSV is `symbol,date,close`, where the benchmark is another explicit symbol. For the existing SP500 display target, `EXPLICIT_STORED_BENCHMARK_SP500` means an explicitly sourced, session-level series matching the application's stored benchmark definition; it does not authorize silently replacing that target with SPY or a differently defined index return. Every `(symbol,date)` must be unique and every supplied close finite and strictly positive. Do not use dividend-adjusted total-return prices against an ex-dividend price-return forecast. Independently verify split/corporate-action handling and a consistent security/benchmark price basis before interpreting errors; the parser does not certify those economic properties.

Optional `init --historical-baseline path/to/baseline.json` consumes a fixed object such as:

```json
{"absolutePct": 0.0, "excessPct": 0.0, "trainingThroughUtc": "2026-10-01T20:00:00Z"}
```

The numbers above illustrate schema only, not a fitted historical baseline. Declare and retain its actual historical training dataset and fitting evidence separately. This tool validates the cutoff declaration and freezes values; it cannot prove training provenance.

## Evidence limits and remaining real work

- The existing archive proves a local saved-output capture, not complete point-in-time input availability. Its underlying V2–V8 raw inputs, release/receipt timestamps, stale cached price age, and source-policy lineage remain unproven. Even a perfectly matured report is descriptive saved-output error, not certification of historical or full-input PIT correctness.
- Create-only files and hashes detect accidental changes; they are not signatures, trusted timestamps, append-only remote storage, or protection against an operator replacing both content and hashes. Preserve protocol, source archives, calendar evidence, prices, and this exact script in durable storage with an independently trustworthy timestamp if stronger evidence is required.
- The sourced scheduled calendar is prepared, but no actual new prospective captures or actual future 20-session outcomes are generated here. Real initialization requires retaining the calendar provenance and a correctly matched benchmark definition. Then collect genuine batch captures after initialization, freeze before entry close, wait for actual maturity, and supply auditable prices. Do not backfill synthetic examples as real data. For a qualified weekend observation anchored October 30, the first scheduled entry is November 2 close and its entry-plus-20-session exit is December 1 close (21:00 UTC); this is calendar arithmetic, not an actual forecast or outcome.
- There is no performance promotion, trading recommendation, net-of-cost return calculation, statistical significance claim, or model change. Every output states `promotion=false`. Prediction calibration, confidence intervals, transaction costs, corporate actions, multiple-testing controls, and full input provenance require separate evidence before any stronger conclusion.

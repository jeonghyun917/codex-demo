# 20D 개선 후속 실행 결과

## 목적과 결론

목적은 지표·가중치가 이후20거래일 예측의 실제 오차를 줄이는지 검증하는 것이다.
코드 안전성·자료 확보·테스트 통과를 예측 정확도 개선으로 바꾸어 부르지 않는다.

이번 실행에서 재무 선택·비교·항목 조립 오류를 수정했고, 다음 실행부터 실제 예측을 별도 파일로 보존하는 배치 경로를 구현했다.
MAE 중심의 추가 모델은 확실한 개선 근거가 없어 운영 적용하지 않았다.
기존 DB 재무 행의 일괄 재작성, 운영 배치 실행/서버 재시작, 새 예측식 배포는 하지 않았다.
따라서 제품 소스 수정 완료와 운영 데이터 정비 완료, 모델 유효성 입증 완료는 서로 다른 상태이다.

## 1. 화면의 실제20D 계약

Quant index 표는 `IndexConstituentMapper.findMarketRows`의
`EXPECTED_RETURN_V9_CORRECTED_20261017.expected_excess_return_pct`를 표시한다.
StockMarketViewService.toViewRow가 그 값을 포맷한다. 확률도 비교지수 초과 확률이다.
기존 dashboard 도움말은 이미 이 차이를 설명하고 있으므로 중복 UI 변경은 하지 않았다.
벤치마크는 저장된 시가총액가중 가격수익률 프록시이며 공식 배당포함 지수와 같지 않다.
종목 상세의 다른 horizon/절대수익률 표시까지 같은 칼럼이라고 일반화하지 않는다.

## 2. 실제 제품 입력 경로 수정

- Historical/current 재무 mapper가 FY/Q 글자만으로 자료를 선택하지 않도록 했다.
  실제 기간: 연간330–380일, 분기70–110일.53주371일은 유지하고9개월/누적반기 등은 제외.
  start/end와 저장period_days가 모순되면 제외한다.
- 과거 공시는 날짜만 있는 경우 같은 날의 공시 시각을 추정하지 않고 `filed_at < asOfDate`로 제한.
- 이전 연간/분기 비교는 인접 기간·동일 통화·연속 회계분기일 때만 허용한다.
- 해외 일반주 EPS를 ADS 가격에 곧바로 나누거나, 비USD EPS를 USD 가격에 나누지 않는다.
  국내10-K의 USD/shares와 명시적으로 정규화한 USD/quoted-security는 유지한다. 임의 FX/ADS 비율 없음.
- 새 FinancialInputPolicy가 HistoricalBacktestSeedService와 StockSignalService의 실제 소비 경로에 적용된다.
  USD 시가총액/비USD 매출로 PS를 계산하는 경우도 제외한다.
- 더 상위 SecFinancialStandardService.RowBuilder도 수정했다. 항목마다 독립적으로 선택해
  CNY매출+USD이익/자산, 연간매출+누적기간이익/OCF/EPS가 한 행에 섞이는 문제를 재현했다.
  하나의 통화·동일한 실제 기간을 기준으로 모든 후보를 재검토하여 호환되는 대안을 보존하고
  호환되지 않는 값은 제외한다. 자산/부채 등은 instant 관측을 유지한다.
  rawJson에 coherencePolicy, selectedFieldEvidence, candidateFieldEvidence로 단위·시작/종료·기간을 남긴다.

현재 Signal 버전은 `q4-fin-20261031`, 역사 재구성은 `q4-hist-fin-20261031`.
기존 현재 화면/백테스트/QuantOpinion의 버전 바인딩을 함께 수정했다.
역사 snapshot 고유키는 버전을 포함하므로 이전 실험과 구별된다.
V9 수식/가중치 버전은 변경하지 않았다. 입력 정정이 예측 성능을 개선했다고 아직 검증하지 않았다.

### 기존 DB의 중요한 잔여 상태

SELECT 집계만 실행했다. 기존 행의 FY표시26,284건 중8,347건은 새 연간 기간 조건에 맞지 않았다.
Q1/Q2/Q3/Q4 부적합 기간 행은 각각57/2,623/2,504/49건이다.
이는 원천 관측 자체가 모두 틀렸다는 뜻이 아니라 **그 라벨로 연간/독립분기 비교에 쓰면 안 되는 행**의 수이다.
새 query는 이런 행을 선택하지 않는다.

그러나 기존 행은 항목별 단위 증거가 없을 수 있어 행 전체의 currency/start/end만으로
내부 항목의 통화·기간 일치를 증명할 수 없다. 상위 조립 코드 수정만으로 기존 DB가 자동 수리되지는 않는다.
일괄 delete/rebuild는 실행하지 않았다. 다음 데이터 정비는 원본 보존·건별 before/after·트랜잭션·누락 방지를 갖춘
선택적 재표준화와 그 후 전체동일구간 재평가가 필요하다. 이를 완료로 표시하지 않는다.
증거: `tmp/quant-20d-financial-readonly-profile.tsv`.

## 3. 실시간 예측 보존 경로

Spring의 V9 최신 배치가20D 행을 저장한 뒤 DB에서 실제 저장값을 다시 읽어
`data/quant-forward/<index>/<signalDate>/<uuid>.json`에 CREATE_NEW로 추가한다.
저장된 decimal값, 실제 UTC 관측시각, SignalDate, V9모델, 현재 앱 재무정책 버전,
V8 upstream snapshot과 사용한 시장 입력을 함께 기록한다.
재계산을 해도 기존 파일을 덮어쓰지 않는다. Git에는 이 런타임 디렉터리를 제외했다.
5D 등 다른 horizon은 기존대로 저장하고20D만 아카이브한다.
파일 기록 실패는 배치 실패 진단에 드러나며 성공으로 삼키지 않는다.
배치용 경로이고 GET 요청에 외부 API나 파일 쓰기를 추가하지 않았다.

검토 중 당일 역사V8을 LIVEV9으로 다시 태깅할 수 있는 문제가 발견됐다.
해당 사례를 RED→GREEN으로 재현하고, Spring 전방 보존 경로는 명시적인 LIVE V8 출처를 요구하도록 했다.
역사 실험의1인자 V9 생성자는 기존 계산 호환용이며 전방 파일 보존을 하지 않는다.

설정: `app.quant.forward-archive.directory` (기본 `./data/quant-forward`).
컨테이너/배포 환경에서는 영속 볼륨으로 지정해야 한다. Railway 설정은 변경하지 않았다.
이 파일은 현재 관측한 모델 출력의 기록이지 전체 V2–V7 원천·도착시각을 증명하는 완전PIT 저장소는 아니다.
일중/서버날짜 관측일 수 있으므로 실제 평가 시 거래소 세션과 진입 전 cutoff를 정한 뒤 사용해야 한다.
서버/실제 배치를 이번 실행에서 구동하지 않았으므로 실제 LIVE 파일이 생성됐다고 주장하지 않는다.

## 4. 고정된 강건 예측 후보 비교

최소8개 성숙 학습일, decision과exit 모두 시험 판단일보다 엄격히 과거.
같은11판단일×101종목, 절대/초과 타깃 분리, 학습 구간만 정규화.
Residual median, QuantileRegressor(q=.5,alpha=.1), Huber(epsilon1.35,alpha.1)를 고정.
결과를 보고 파라미터를 탐색하지 않았다. 이미 본 역사자료의 탐색적 후속 실험이다.

조건부 중앙값과 기대수익률(조건부 평균)은 서로 다르므로 의미를 바꾸어 화면에 넣지 않는다.
정확도가 좋아졌다는 주장, 유의성 주장, 새 확률·구간 보정·운영 가중치 적용 없음.

최종: `tmp/quant-20d-robust-research-v6-20261031/`의 README/result/summary/verification.
17,776저장예측·176일별그룹·132fit·46hash를 독립 stdlib validator로 확인.
기존 source hash는 현재 코드 변경을 적발했으므로 변경 전 V9의 정확한 원래 hash와 일치하는
snapshot을 복원·보존해 검증했다. 원래 자료/해시를 우회하거나 새 코드가 예전과 같다고 주장하지 않는다.

무료로 현재 받을 수 있다는 사실을 과거 도착시각/이용권/PIT 완전성으로 바꾸어 부르지 않는다.
